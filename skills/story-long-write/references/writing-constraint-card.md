# 续写约束卡

> 整合自 novel-continuity-manager 的「续写前约束卡」机制。
> 写作目标：在写每章正文前，先在心里（或草稿中）过一遍约束卡，确认要写的内容不打破已有的连续性。

## 用法

在 Step 2 逐章写作前，按以下流程从已加载的文件中提取约束信息，形成一句话摘要。**不需要写成正式文件，也不需要全部写出来；只用记录不能靠记忆确认的关键约束。**

---

## 约束维度

### 1. 当前局势摘要（一句话）

从 `追踪/上下文.md` 和上一章正文提取：主角在哪，刚发生什么，当前主要矛盾是什么。

### 2. 不可违背的已确认事实

从角色设定和追踪文件提取本章必须保持的、已在前文确认的事实。**哪些是这章不能碰的？**

常见陷阱：
- 角色已受伤/已消耗的蓝量/已损坏的装备 — 不能无恢复地正常使用
- 已确认的位置限制 — 角色不能瞬移
- 已确认的知识边界 — 角色不该知道的事不能突然知道

### 3. 角色状态边界

从 `追踪/角色状态.md` 提取本章涉及角色的关键状态摘要：

| 人物 | 状态约束 |
|------|----------|
| 林月 | 左臂旧伤，近战受限；不知幕后黑手身份 |
| 赵六 | 已死亡，不能出场 |
| 苏念 | 不知林月的真实身份 |

### 4. 物品与资源限制

从 `设定/道具清单.md` 或 `追踪/` 提取本章涉及物品的关键约束：

| 物品 | 约束 |
|------|------|
| 黑钥匙 | 在林月手上；只能开一扇门（已用） |
| 回血丹 | 只有 1 颗（已用） |

### 5. 角色知识边界

确保每个角色的对话、内心独白、决策不超出其信息范围：

- 角色 A 知道什么、不知道什么、不应该知道什么
- 读者知道什么、角色知道什么 — 区分两者，不要错位

### 6. 活跃伏笔

从 `追踪/伏笔.md` 提取本章**可推进**和**不应推进**的伏笔：

- 可推进：主动推进或暗示某条伏笔
- 应避免：信息泄露，提前揭露尚不到时机的真相
- 必回收：如果本章是预计回收章节，确保不遗漏

### 7. 暂不宜揭露的信息

列出作者设定中尚不到揭露时机的信息。**写了就会破坏悬念的内容：**

- 幕后黑手的真实身份（预计第 40 章才揭露）
- 主角的血脉秘密（卷末高潮才揭晓）

### 8. 时间线与地点约束

- 当前时间点（第几天/第几年？季节？白天/夜晚？）
- 可用地点（角色能出现在哪？不能出现在哪？）
- 路程需要的时间（两地移动是否合理？）

## 知识边界处理流程（关键步骤）

这是最难自动化也最容易出错的维度。续写时必须按以下步骤系统性地处理角色信息边界，不能靠直觉或记忆。

### Step A：列出本章涉及的角色

从细纲和上一章结尾提取。分为三类：
- **出场角色**（有对话/行动）→ 必须逐人检查
- **被提及角色**（只被提到名字）→ 只需确认提及内容不越界
- **不出场角色** → 忽略

### Step B：对每个出场角色，从设定中分离三类信息

从该角色的设定文件（`设定/角色/{角色名}.md`）或 `追踪/角色状态.md` 中提取：

```
角色：林月
├── 已知（立场、目标、当前处境）
│   ├── 林月知道自己左臂受伤
│   ├── 林月知道苏念是她师姐
│   └── 林月知道赵六已死
├── 未知（不该知道的真相）
│   ├── 林月不知道自己是被选中的祭品（作者真相）
│   └── 林月不知道幕后黑手是师尊（作者真相）
└── 不应知道（如需知道必须有交代渠道）
    └── 苏念隐藏的身份（除非苏念本章告诉了她）
```

**来源映射**：
- `已知` → 设定文件中角色已亲身经历或被明确告知的事件
- `未知` → 未在正文中向该角色揭示的信息
- `不应知道` → 其他角色的秘密或作者真相中该角色未涉及的层面

如果设定文件中没有显式的知识清单，从以下来源推断：
- `已知` ← 该角色出场的各章正文/该角色参与的追踪事件
- `未知` ← 仅在其他角色视角/旁白中出现的信息
- `不应知道` ← 其他角色设定中的秘密字段、追踪/伏笔.md 中标记为未回收的伏笔核心

### Step C：对比本章计划内容，标记越界风险

列出本章要写的场景/对话/事件，逐条问：

| 检查项 | 问句 | 如果违反 |
|--------|------|----------|
| 对话越界 | A 是否在对话中透露了 B 不该知道的信息？ | 要么删对话，要么加 B 提前获知的渠道 |
| 内心越界 | 角色内心独白是否包含其未知的信息？ | 删掉该独白 |
| 旁白越界 | 叙述者的描述是否超出了当前所有角色的认知？ | 判断是否确实需要（大多数情况不需要） |
| 动作越界 | 角色是否基于其未知的信息做出了决策？ | 要么改决策理由，要么提前让角色获知 |

### Step D：检查旁白/描述中的信息泄露（AI 写作高发区）

这是 AI 写作最容易踩的坑。写作时必须问自己：

> 我正在写的这个描述句，当前场景中的角色能看到/知道吗？

典型违规：
- 旁白写了幕后黑手的真实想法，但主角并不在场（信息给了读者但超出了主角认知）
- 描述角色表情时用了「他眼中闪过一丝不易察觉的愧疚」—— 但当前视角角色的角度根本看不到
- 叙述中提前揭示了伏笔的答案

**安全写法**：旁白信息不应超出主角（或当前视角角色）的认知范围。如果需要给读者超出主角认知的信息，必须是有意设计的「观众知道但角色不知道」的悬念，而不是无意的信息泄露。

### Step E：形成知识边界约束

把以上处理结果压缩为 2-3 条写入意图确认的连续性约束部分：

```
约束：苏念不知道林月的真实身份 → 本章对话中林月不能主动暴露；苏念推理可以有怀疑但不到确认。
约束：读者尚不知道师尊是幕后黑手 → 旁白不能出现师尊的内心活动或暗示性描述。
约束：林月不知道封印的秘密 → 她的决策不能基于「需要保存封印力量」这个理由。
```

## 实际写入流程

在 Step 2 写作循环中，约束卡嵌入在"状态筛选"和"意图确认"之间：

```
状态筛选完成后
  → 在脑中快速过一遍约束卡 8 维（30 秒）
  → 识别出 2-3 个最关键的本章约束
  → 把这些约束写进意图确认的一句话描述里
  → 开始写正文
```

不需要把完整的约束卡写进任何文件。如果某个约束你无法靠记忆确认，**停下来用 grep 搜索确认再写**。

## 常见连续性错误（写作时特别留意）

| 错误类型 | 典型表现 | 预防方法 |
|----------|----------|----------|
| 知识越界 | A 角色知道 B 角色才该知道的秘密 | 写对话前确认信息权限 |
| 物品滥用 | 已消耗的道具再次使用 | 写道具前确认剩余数量 |
| 伤病跳跃 | 上一章重伤，这一章无恢复描写就正常行动 | 要么写恢复过程，要么限制行动 |
| 位置瞬移 | 不在同一地点但无路程交代 | 确认角色上一章结尾的位置 |
| 能力破限 | 有冷却/代价的能力连续使用 | 写能力前确认限制条件 |
| 称呼错位 | 关系已变但称呼未变 | 写称呼时确认当前关系阶段 |
| 伏笔泄露 | 通过旁白提前透露真相 | 旁白信息不能超出角色当前所知 |
